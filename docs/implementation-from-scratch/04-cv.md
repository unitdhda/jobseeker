# Assignment 04 — `@jobseeker/cv`

## Scope

Build deterministic CV extraction and PDF rendering as two separately importable subpaths:

- `@jobseeker/cv/extract` for file parsing and canonical source evidence;
- `@jobseeker/cv/pdf` for structured documents, evidence validation, and Typst rendering.

The package must not know users, models, persistence, or environment variables.

## Files

```text
packages/cv/src/
├── extract.ts
├── document.ts
├── evidence.ts
├── template.ts
├── render.ts
└── pdf.ts
```

## 1. Extraction contracts

Define:

```ts
type CvSourceFormat = 'pdf'|'md'|'txt'|'docx';
interface CvBlockProvenance { start: number; end: number; page?: number }
type CvDocumentBlock =
  | { type:'heading'; text:string; level:number; source?:CvBlockProvenance }
  | { type:'paragraph'; text:string; source?:CvBlockProvenance }
  | { type:'list-item'; text:string; source?:CvBlockProvenance }
  | { type:'table'; rows:string[][]; source?:CvBlockProvenance };
type CvExtractionWarningCode =
  | 'no-headings'|'no-dates'|'duplicate-content'|'possible-column-order';
interface CvExtractionWarning { code:CvExtractionWarningCode; detail:string }
interface CanonicalCvDocument { version:1; blocks:CvDocumentBlock[]; warnings?:CvExtractionWarning[] }
interface ExtractedCvDocument {
  text:string; document:CanonicalCvDocument; sourceFormat:CvSourceFormat;
  mediaType:string; parserName:string; parserVersion:string;
}
```

Maximum upload is 20 MiB; maximum normalized text is 500,000 characters.

## 2. Safe format detection

Use filename extension, media type, and magic bytes together.

- Supported extensions: PDF, DOCX, MD/Markdown, TXT.
- PDF must begin `%PDF`.
- DOCX must be a ZIP signature.
- Reject extension/content disagreement.
- Reject unsupported extensions even if the media type is generic.
- Text decoding is strict UTF-8 with Windows-1251 fallback.

Before Mammoth receives DOCX, inspect the ZIP central directory and reject:

- no readable entries;
- truncated directory;
- ZIP64;
- more than 2,000 entries;
- more than 50 MiB uncompressed;
- compression ratio over 100.

## 3. Per-format extraction

### PDF

- Configure PDF.js lazily through unpdf.
- Merge pages.
- If non-whitespace text is under 100 characters, throw a specific `CV_OCR_REQUIRED` error.
- Normalize to plain blocks and annotate offsets.

### DOCX

- Run raw text and HTML conversion.
- Prefer canonical blocks from semantic HTML headings/paragraphs/lists/tables.
- Fall back to raw plain blocks.
- Annotate offsets.

### Markdown

Parse headings, lists, paragraphs, tables, blockquotes, and fenced code conservatively. Remove inline link/image/format markers without interpreting arbitrary HTML.

### Text

Detect all-uppercase short headings and common bullet markers; otherwise keep paragraphs.

### Shared normalization

- NFC normalization;
- remove NUL and normalize NBSP/newlines/tabs;
- trim trailing spaces and collapse excessive blank lines;
- reject under 100 or over 500,000 characters;
- canonical document text joins block content consistently;
- annotate each recoverable block with source offsets;
- emit warnings for no heading, no four-digit date, duplicate long content, and likely interleaved columns.

Implement `detectCvLanguage` as `ru|en`, choosing Russian only with meaningful Cyrillic evidence.

## 4. Structured tailored-CV document

Define limits:

```ts
const cvDocumentLimits = {
  contacts: 8,
  sections: 14,
  blocksPerSection: 40,
  bullets: 30,
  facts: 20,
} as const;
```

Define:

```ts
interface CvDocument {
  name: string;                 // required, <=120
  headline?: string;            // <=200
  contacts: string[];           // <=8, each <=160
  sections: Array<{
    title: string;              // <=80
    blocks: Array<
      | { kind:'text'; text:string }
      | { kind:'bullets'; items:string[] }
      | { kind:'entry'; title:string; subtitle?:string; meta?:string;
          text?:string; bullets?:string[] }
      | { kind:'facts'; items:Array<{term:string;detail:string}> }
    >;
  }>;
}
```

Use Valibot for exact bounds. Contact objects drifted from models may be reduced from `value|text|url|handle|label`.

## 5. Repair and plain-text salvage

`normalizeCvDocumentJson` is a last-resort repair after model retries. It may:

- unwrap `cv` or `document`;
- map `type` to `kind`;
- convert strings to text blocks;
- map `company/employer/organization/institution/name` to entry title;
- map role/position/degree, period/dates/date/location, summary/description, and points/bullets;
- coerce facts and contact arrays;
- clip every schema-bound collection;
- drop unrecognizable debris and empty sections.

`parseCvText` must salvage a prose CV conservatively:

- require enough content;
- infer a small header only;
- avoid treating acronym lists as headings;
- merge hard-wrapped paragraphs until blank line;
- attach bullets to the preceding entry;
- move date tails into entry metadata;
- parse short label/value rows as facts;
- avoid donating an unstructured body to contacts.

## 6. Deterministic evidence gate

Define:

```ts
interface CvEvidenceIssue {
  kind:'new-number'|'unknown-entry'|'unknown-contact'|'unsupported-skill';
  value:string;
}
```

`tailoredCvEvidenceIssues(document, authoritativeText)` must detect:

- numeric claims absent from source;
- contact values absent from source;
- employer/institution entry titles absent from source;
- named skills in facts absent from source.

Normalize formatting and allow only explicit aliases such as JS/JavaScript, TS/TypeScript, Postgres/PostgreSQL, K8s/Kubernetes, and named RAG/LLM/GenAI expansions. Do not use another model for fact checking.

`assertTailoredCvEvidence` throws a bounded summary of the first eight issues.

## 7. Typst source generation

`cvSource(document,density)` must:

- escape every Typst-sensitive character, including punctuation Typst rewrites;
- consume only `**bold**` and `*italic*` inline markers;
- serialize arrays as one-element-safe tuples with trailing commas;
- place entry dates in metadata;
- choose Russian/English document language;
- emit only calls into a fixed preamble/component library.

Reject Typst source containing `import`, `include`, or `read`.

The template must own all styling:

- A4 dimensions and fixed margins;
- Spectral body and JetBrains Mono labels;
- ATS-readable text without letter spacing;
- accent/header/section/list/entry/facts/text components;
- sticky section and entry headers;
- no arbitrary model-supplied Typst.

## 8. Rendering factory

Define:

```ts
interface CvPdfOptions { fontPaths?: readonly string[] }
interface CvPdf {
  compileTypst(source:string): Buffer;
  compileCvDocument(document:CvDocument): Buffer;
  compilePlainTextCv(text:string): Buffer;
}
```

`createCvPdf` closes over one compiler and receives font paths explicitly.

Rendering requirements:

1. verify compiler diagnostics and output `%PDF`;
2. compile natural density first;
3. if multi-page, try `0.96,0.93,0.90,0.87,0.84,0.82`;
4. accept the first density reducing page count;
5. otherwise retain natural output rather than over-compressing;
6. expose plain-text salvage through the same structured path.

## 9. App-side parser isolation

The app must add a separate `cv-worker` process:

- 30-second timeout;
- 256 MiB heap ceiling;
- maximum two concurrent parser processes;
- built Node worker runs with filesystem permissions restricted to bundle/node_modules;
- source checkout may use Bun worker;
- minimal environment only;
- IPC with one request/result;
- force-kill and decrement counters on every settlement path.

The app computes upload SHA-256, stages the extraction, and returns a preview with filename, character/block counts, first 700 characters, and warnings. Confirmation, not extraction, replaces the authoritative CV.
