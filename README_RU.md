# Jobseeker

**Самостоятельно разворачиваемый Telegram-сервис, который непрерывно ищет вакансии, оценивает их по резюме и помогает готовить отклики.**

Загрузите резюме один раз. Jobseeker превратит его в запросы для нескольких площадок, нормализует и дедуплицирует
новые объявления, оценит каждую вакансию относительно вашего опыта и отправит лучшие совпадения в Telegram. Если
вакансия заинтересовала, адаптированное резюме или сопроводительное письмо можно запросить прямо из уведомления.

## Что он делает

Jobseeker — не очередной интерфейс для просмотра джоб-борда. Это непрерывно работающая поисковая система вокруг
резюме каждого пользователя:

1. **Понимает резюме** — извлекает пригодную для повторного использования структуру и создаёт поисковый спрос по ролям.
2. **Следит за площадками** — запускает общие адаптивные поиски и сохраняет каждое объявление один раз.
3. **Фильтрует до дорогих вызовов** — отбрасывает слабые лексические совпадения до обращения к LLM и заново настраивает
   этот фильтр по собственным прошлым оценкам, чтобы бюджет уходил на самые перспективные вакансии.
4. **Оценивает соответствие** — учитывает навыки, уровень, обязанности, локацию, формат работы и жёсткие ограничения.
5. **Доставляет решения** — сразу присылает сильные совпадения, а подходящие для просмотра собирает в дайджест.
6. **Помогает откликнуться** — готовит адаптированное резюме или письмо только по запросу пользователя.

## Как это работает

```text
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Загрузка резюме               │     │ Адаптированное резюме/письмо  │
└───────────────────────────────┘     └───────────────────────────────┘
                │                                      ▲
                ▼                                      │
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Компиляция поискового спроса  │     │ Telegram-алерт или дайджест   │
└───────────────────────────────┘     └───────────────────────────────┘
                │                                      ▲
                ▼                                      │
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Мониторинг площадок           │     │ Бюджетная LLM-оценка          │
└───────────────────────────────┘     └───────────────────────────────┘
                │                                      ▲
                ▼                                      │
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Общая база вакансий           │ ──▶ │ Сопоставление с каждым резюме │
└───────────────────────────────┘     └───────────────────────────────┘
```

Поиски адресуются по содержимому: одинаковый спрос разных пользователей превращается в одну поисковую единицу, но
сопоставление и оценка остаются персональными. Новое объявление нормализуется один раз, проверяется лексической
линзой каждого одобренного пользователя, и только перспективные пары попадают в LLM-очередь. Обнаружение и оценка
работают независимо, поэтому медленный браузерный источник не блокирует скоринг и доставку в Telegram.

## Что приходит в Telegram

Уведомление должно помогать принять решение, а не просто сообщать URL:

- калиброванная оценка соответствия от `0` до `100`;
- короткий комментарий;
- конкретные причины, почему вакансия подходит;
- пробелы или требования, которые стоит проверить;
- ссылка на оригинал;
- действия для резюме, письма или пропуска вакансии.

Готовые материалы переиспользуются, пока исходное резюме не изменилось. Повторный запрос отправляет тот же документ
без нового вызова модели; загрузка нового резюме естественным образом инвалидирует кэш.

## Зачем Jobseeker

| Возможность | Какую проблему решает |
|---|---|
| **Непрерывный поиск** | Запросы из резюме выполняются по адаптивному расписанию вместо ручного просмотра площадок. |
| **Фильтрация до расходов на AI** | Дешёвое лексическое сопоставление не пускает заведомо слабые вакансии в дорогую очередь. |
| **Общее обнаружение** | Найденное для одного пользователя объявление можно оценить для других без повторной загрузки. |
| **Нет повторной доставки** | Переходы состояния в PostgreSQL не позволяют заново прислать просмотренную или обработанную вакансию. |
| **Материалы для отклика** | Адаптированные резюме и письма генерируются независимо и мгновенно отправляются повторно. |
| **Независимость от AI-провайдера** | Для скоринга и генерации можно выбрать разные модели из каталога Pi AI. |
| **Наблюдаемая работа** | Скрытые команды владельца показывают расходы, состояние источников, ошибки парсинга и деплой. |

## Источники вакансий

**Приложение само не регистрирует ни одного источника.** Источники приходят из расширений: при старте сервис
загружает ESM-модули из `./extensions` (переопределяется через `JOBSEEKER_EXTENSIONS`) и вызывает у каждого
экспортированную по умолчанию функцию `register(api)`. `@jobseeker/sources` даёт им runtime: контракт провайдера,
регистрацию в рамках экземпляра, явно передаваемый контекст, границу HTTPS/SSRF, универсальные драйверы для тех
поверхностей, которые реально публикуют сайты, и готовые примеры провайдеров примерно для 19 публичных источников.

| Драйвер | Поверхность источника | Примеры провайдеров |
|---|---|---|
| `createApiSource` | Постраничные JSON-списки и опциональная JSON-карточка | Ozon Careers, RWB / Wildberries, Вакансии МТС |
| `createAtsSource` | Борды Greenhouse, Lever, Ashby, SmartRecruiters | Настраиваемые борды компаний `provider:slug` |
| `createCompanySiteSource` | Собственный JSON-поиск компании и HTML-страницы вакансий | Вакансии Яндекса, Вакансии VK |
| `createJsonLdBoardSource` | Перечисляемые борды с разметкой schema.org `JobPosting` | Avito Careers, Geekjob, Вакансии Контура |
| `createSourceProvider` | Всё остальное, включая браузерные источники | Habr Career, Rabota.ru, HireHi, Работа России и hh.ru — эталонное расширение `hh` (постоянный Playwright) |

Провайдер объявляет все хосты, к которым может обращаться, ходит в сеть только через переданный HTTP-клиент и
регистрируется независимо от участия в поиске: это отдельно решает `SEARCH_PLATFORMS`. Источник может оставаться
зарегистрированным для нормализации и проверки URL, не создавая новых поисков. Свои зависимости расширение держит
при себе: браузерный источник хранит Playwright рядом с собой, а не в приложении.

Доступность источника зависит от сетевого выхода сервера и текущего поведения площадки. Наличие примера не означает,
что его следует включать в каждом деплое: проверяйте источник с той машины, которая будет выполнять поиск.

[Руководство по расширениям →](extensions/README.md) · [Руководство по runtime провайдеров и драйверам →](packages/sources/README.md)

## Развернуть свой экземпляр

Jobseeker публикуется как [`@unitdhda/jobseeker`](https://www.npmjs.com/package/@unitdhda/jobseeker) — одна команда,
настраиваемая только переменными окружения:

```bash
npm install @unitdhda/jobseeker

export DATABASE_URL=postgres://… TELEGRAM_BOT_TOKEN=… TELEGRAM_USER_ID=…
export AI_MODEL=provider/model AI_SCORING_MODEL=provider/model

npx jobseeker db init            # применить схему из пакета к пустой базе
npx jobseeker credentials create # вход у AI-провайдера: OAuth или API-ключ
npx jobseeker doctor             # конфигурация, база, шрифты, расширения
npx jobseeker start              # приёмник Telegram + цикл движка + health-эндпоинты
```

Понадобятся Node.js 23.6+ или Bun 1.3+, PostgreSQL 15+, токен Telegram-бота с аккаунтом владельца и учётные данные
хотя бы одного провайдера Pi AI. Шрифты для PDF идут внутри пакета. Источники вакансий — нет: пока не добавлено ни
одного расширения, поиск ничего не делает.

Безопасный путь настройки охватывает инициализацию базы, AI-авторизацию, владение Telegram, расширения-источники и
инвариант единственного приёмника:

**[Открыть руководство по self-hosting →](docs/self-hosting.md)**

Настройку и добавление источника удобно поручить кодинг-агенту, оставив себе проверку доказательств и диффа.
Скопируйте один из промптов:

### Настроить экземпляр

```text
Install @unitdhda/jobseeker from npm and configure a private instance for me. Read and follow its README,
docs/self-hosting.md, and .env.example from https://github.com/unitdhda/jobseeker; ask me for missing choices and
credentials without exposing or committing secrets. Initialize the database with `jobseeker db init`, write an
extension that registers the vacancy sources I choose, preserve the single-Telegram-receiver invariant, and get
`jobseeker doctor` passing plus /health and /ready before handing back.
```

### Добавить источник вакансий

```text
Add <source name and listing URL> to my Jobseeker instance as a vacancy source. Read extensions/README.md and
packages/sources/README.md from https://github.com/unitdhda/jobseeker first. Probe the public JSON or HTML surface
and show the evidence, then pick the closest reusable driver (or createSourceProvider directly). Write it as an
extension in my extensions directory, declare every host, fetch only through context.http, keep raw queries out of
traces, and install any dependency it needs in that directory. Show me the source's funnel in /scraper before
leaving it enabled.
```

Чтобы дорабатывать само приложение, клонируйте репозиторий:

```bash
bun install --frozen-lockfile
bun run typecheck
bun run test
bun run build
bun --env-file=.env packages/app/dist/server.mjs   # или: node --env-file=.env packages/app/dist/server.mjs
```

`/health` показывает состояние процесса, `/ready` дополнительно проверяет PostgreSQL.

## Технический обзор

Jobseeker — монорепозиторий на Bun workspaces, работающий на Node или Bun (Bun-специфичные API не используются).
Доменные пакеты собираются пакетом приложения — именно он публикуется в npm.

| Workspace | Ответственность |
|---|---|
| `packages/engine` | Идентичность поисков, компиляция спроса, адаптивный ритм, планирование, правила состояний |
| `packages/store` | PostgreSQL-клиент и репозитории |
| `packages/sources` | Открытый runtime провайдеров, контракты, SSRF/HTTP-политика и переиспользуемые драйверы |
| `packages/cv` | Извлечение резюме и генерация PDF через Typst |
| `packages/app` | Публикуемый пакет `@unitdhda/jobseeker`: CLI, конфигурация, runtime движка, Telegram, workflow, модели, воркеры, загрузка расширений и схема базы |

PostgreSQL — единственная runtime-база, а `packages/app/schema.sql` — её единственная схема: серии миграций нет.
Расписание обнаружения хранится в `search_units.next_run_at`, а цикл движка берёт advisory lock в PostgreSQL, так что
второй процесс с `RUN_JOBS=true` простаивает, а не дублирует работу. У Telegram такой защиты нет: обновления по
одному токену может принимать только один процесс.

## AI-провайдеры и стоимость

Все вызовы проходят через [Pi AI](https://github.com/earendil-works/pi-ai). Модели выбираются конфигурацией, а не кодом:

- `AI_MODEL` — поисковые профили и материалы для отклика;
- `AI_SCORING_MODEL` — массовая оценка вакансий;
- `AI_SCORING_FALLBACK_MODEL` — опциональная резервная модель;
- `AI_AUTH_FILE` — хранилище учётных данных по провайдерам.

Встроенные провайдеры могут использовать API-ключи или OAuth, а расширение может зарегистрировать собственного
провайдера. `usage_events` хранит модель, классы токенов и оценку
стоимости по каталогу. Для OAuth и подписок это эксплуатационная оценка, не обязательно сумма из счёта.

## Приватность

Jobseeker обрабатывает резюме и поисковые предпочтения. Оператор отвечает за защиту PostgreSQL, Telegram-токена и
учётных данных моделей.

- **Сервер Jobseeker** не хранит исходный загруженный файл резюме; Telegram может сохранять файлы в соответствии со
  своим поведением и политиками.
- Извлечённый текст и структура резюме сохраняются для повторного поиска и генерации.
- Текст резюме и вакансии передаётся настроенному AI-провайдеру для профилей, оценки и адаптации.
- Пользователи одной инсталляции разделяют **формулировки поисковых запросов** — но не имена, контакты или текст
  резюме. Одинаковый спрос становится одним поиском и выполняется один раз, а существующая формулировка может быть
  предложена без указания автора при формировании поискового профиля другого пользователя. Сопоставление и оценка
  остаются приватными для каждого пользователя.
- Текст письма и Telegram file ID отправленного PDF могут сохраняться для мгновенной повторной отправки; байты PDF
  в PostgreSQL не хранятся.
- `/export_me` экспортирует сохранённые персональные данные.
- `/delete_me confirm` удаляет резюме, профили, совпадения, материалы, usage и настройки доставки, сохраняя только
  запись о доступе пользователя.

## Статус проекта

Jobseeker — используемый в продакшене персональный сервис, а не публичный SaaS. Один деплой рассчитан на небольшое
число пользователей и предполагает оператора, знакомого с Docker, PostgreSQL, Telegram-ботами, браузерной
автоматизацией и учётными данными моделей.

Проект активно разрабатывается. Перед тем как давать доступ другим пользователям, изучите схему, правила хранения
данных, адаптеры источников и руководство по эксплуатации.
