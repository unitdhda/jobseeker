# Jobseeker

**Самостоятельно разворачиваемый Telegram-сервис, который непрерывно ищет вакансии, оценивает их по резюме и помогает готовить отклики.**

Загрузите резюме один раз. Jobseeker извлечёт из него переиспользуемый карьерный профиль, скомпилирует общие поиски
по источникам вакансий, нормализует и дедуплицирует новые объявления и сопоставит каждую вакансию с опытом каждого
одобренного пользователя. Лучшие совпадения придут в Telegram, а адаптированное резюме или сопроводительное письмо
можно запросить прямо из уведомления.

## Что он делает

Jobseeker — не очередной интерфейс джоб-борда. Это непрерывно работающий конвейер поиска и подготовки откликов,
построенный вокруг резюме каждого пользователя:

1. **Понимает резюме** — безопасно извлекает PDF, DOCX, Markdown или текст, показывает предупреждения и создаёт нейтральный к профессии карьерный профиль.
2. **Компилирует поисковый спрос** — превращает профили для конкретных провайдеров в общие поисковые единицы с адресацией по содержимому.
3. **Следит за источниками** — запускает наступившие поиски по адаптивному расписанию через расширения развёртывания.
4. **Фильтрует до дорогих вызовов** — применяет детерминированные персональные признаки и опциональную малую семантическую модель до полного скоринга.
5. **Оценивает соответствие** — учитывает навыки, уровень, обязанности, локацию, формат работы и жёсткие ограничения в рамках бюджета пользователя.
6. **Доставляет решения** — сразу присылает высокие оценки, собирает остальные интересные роли в дайджест и готовит материалы для отклика по запросу.

## Как это работает

```text
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Загрузка и подтверждение CV   │     │ Адаптированное резюме/письмо  │
└───────────────────────────────┘     └───────────────────────────────┘
                │                                      ▲
                ▼                                      │
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Компиляция общего спроса      │     │ Telegram-алерт или дайджест   │
└───────────────────────────────┘     └───────────────────────────────┘
                │                                      ▲
                ▼                                      │
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Контур поиска расширений      │     │ Бюджетная AI-оценка           │
└───────────────────────────────┘     └───────────────────────────────┘
                │                                      ▲
                ▼                                      │
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ Общая база вакансий           │ ──▶ │ Сопоставление с каждым CV     │
└───────────────────────────────┘     └───────────────────────────────┘
```

Одинаковый спрос разных пользователей превращается в одну стабильную поисковую единицу, но сопоставление, оценка и
доставка остаются персональными. Обнаружение сохраняет глобально дедуплицированные объявления; затем нормализация
проверяет каждое объявление лексической линзой каждого одобренного пользователя. Только перспективные пары проходят
семантический прескоринг и полный скоринг. Поиск и оценка работают независимо, поэтому медленный источник не блокирует
скоринг или доставку в Telegram.

Единственное расписание поиска хранится в `search_units.next_run_at`. Один процесс владеет циклом движка через advisory
lock PostgreSQL `jobseeker-engine-loop`; владение Telegram не связано с этой блокировкой и обеспечивается оператором.

## Что приходит в Telegram

Уведомление несёт всё, что нужно для решения:

- семантическую оценку соответствия `0–100`;
- короткий вывод и объяснение оценки;
- конкретные причины, почему вакансия подходит;
- пробелы или требования, которые стоит проверить;
- ссылку на оригинал;
- действия для адаптированного резюме, письма или пропуска вакансии.

В каждом сообщении с вакансией показан полный шестибуквенный код, а жирным выделен его кратчайший префикс, уникальный
среди вашей истории оценённых совпадений. Отправьте этот или более длинный префикс обычным сообщением, чтобы получить
вакансию и кнопки «Открыть», «Письмо» и «CV». Если префикс позже станет неоднозначным, полный код останется видимым.

Готовые материалы кэшируются по хешу авторитетного резюме. Повторный запрос использует уже созданный материал без
нового вызова модели; подтверждение нового резюме естественным образом инвалидирует старый кэш.

Бот говорит по-русски и по-английски. Сначала используется поддерживаемый язык клиента Telegram, запасным служит
`BOT_LOCALE`, а `/language` сохраняет выбор пользователя для диалогов, алертов и дайджестов. Написанные моделью оценки
и материалы для отклика используют язык вакансии.

## Зачем Jobseeker

| Возможность | Какую проблему решает |
|---|---|
| **Непрерывный поиск** | Запросы из резюме выполняются по адаптивному расписанию в базе данных. |
| **Проверка до расходов на AI** | Детерминированные признаки и опциональный семантический прескоринг ограничивают дорогую очередь. |
| **Общее обнаружение** | Найденное для одного пользователя объявление можно оценить для других без повторной загрузки. |
| **Нет повторной доставки** | Защищённые переходы PostgreSQL не дают снова показать доставленные, пропущенные или обработанные совпадения. |
| **Материалы для отклика** | Проверенные по исходным фактам резюме и письма генерируются независимо и могут отправляться повторно. |
| **Независимость от AI-провайдера** | Модели генерации, прескоринга, скоринга и fallback настраиваются независимо через Pi AI. |
| **Наблюдаемая работа** | Команды владельца показывают usage, состояние источников, ошибки парсинга, пользователей и деплой. |
| **Язык пользователя** | Сообщения, кнопки, меню команд, алерты и дайджесты используют сохранённую локаль каждого человека. |

## Источники вакансий

**Приложение не содержит встроенного каталога конкретных источников.** При старте оно загружает ESM-модули из
`./extensions` (путь переопределяется через `JOBSEEKER_EXTENSIONS`) и вызывает у каждого экспортированную по умолчанию
функцию `register(api)`. Внедрённый API предоставляет регистрацию источников и AI-провайдеров, lifecycle-хуки,
изолированное логирование, ограничение параллелизма, опциональное зашифрованное состояние и безопасный source toolkit.

`@jobseeker/sources` владеет контрактами провайдеров в рамках экземпляра, парсерами и границей HTTPS/SSRF. Обычный
сетевой трафик источника обязан идти через внедрённый HTTP-клиент: провайдер объявляет все хосты, DNS должен разрешаться
в публичные адреса, редиректы проверяются заново, а размеры ответов и media type ограничены.

| Драйвер | Поверхность источника |
|---|---|
| `createApiSource` | Постраничные JSON-списки и опциональная JSON-карточка |
| `createAtsSource` | Настраиваемые борды Greenhouse, Lever, Ashby и SmartRecruiters |
| `createCompanySiteSource` | Собственный JSON-поиск и канонические HTML-страницы вакансий |
| `createJsonLdBoardSource` | Перечисляемые борды с карточками schema.org `JobPosting` |
| `createSourceProvider` | Специализированные и браузерные источники, которым не подходит общий драйвер |

В `packages/sources/examples` находятся 19 эталонных провайдеров для копирования в развёртывание; runtime приложения
никогда их не импортирует. Используйте либо весь каталог, либо выбранные файлы провайдеров, установите локальные
зависимости расширения и отдельно включите поиск через `SEARCH_PLATFORMS`.

Два полных расширения показывают актуальный runtime: `extensions/hh` владеет сериализованным браузерным источником
hh.ru, а `extensions/claude-cli` регистрирует локальный или private-sidecar провайдер Pi AI. Браузерная навигация должна
проходить ту же политику URL и DNS, что и обычный HTTP-трафик; зависимости расширения хранятся рядом с ним.

Доступность источника зависит от сетевого выхода сервера и текущего поведения площадки. Проверяйте его с той машины,
которая будет выполнять поиск, прежде чем оставлять источник включённым.

[Руководство по расширениям →](extensions/README.md) · [Runtime провайдеров и драйверы →](packages/sources/README.md)

## Развернуть свой экземпляр

Jobseeker публикуется как [`@unitdhda/jobseeker`](https://www.npmjs.com/package/@unitdhda/jobseeker):

```bash
npm install -g @unitdhda/jobseeker

jobseeker --env-file=/path/to/jobseeker.env db init
jobseeker --env-file=/path/to/jobseeker.env credentials create
jobseeker --env-file=/path/to/jobseeker.env doctor
jobseeker --env-file=/path/to/jobseeker.env start
```

Скопируйте [`.env.example`](.env.example) и настройте PostgreSQL, Telegram, модели генерации и скоринга, учётные данные
и хотя бы одно расширение-источник. Понадобятся Node.js 23.6+ или Bun 1.3+, PostgreSQL 15+, токен Telegram-бота и
аккаунт владельца, а также учётные данные хотя бы одного провайдера Pi AI. Шрифты для PDF входят в пакет.

`db init` применяет схему из пакета **только к пустой схеме PostgreSQL `public`** и отказывается работать при наличии
любой таблицы. Существующим установкам нужна проверенная forward-миграция; никогда не запускайте инициализацию поверх
продакшена. Все команды принимают `--env-file`, а переменные уже запущенного процесса имеют приоритет над файлом.

Обновления одного Telegram-бота может принимать ровно один процесс. В polling-режиме у токена не должно быть webhook,
а в webhook-режиме ничто не должно запускать polling. Advisory lock движка не защищает владение Telegram.

Для усиленного контейнера Node 24, Compose-топологии, правил резервного копирования, обновления и отката используйте
**[эталонный VPS-деплой →](docker/README.md)**.

Настройку можно поручить кодинг-агенту. Скопируйте этот промпт:

```text
Install @unitdhda/jobseeker from npm and configure a private instance for me. Read README.md, .env.example,
docker/README.md, extensions/README.md, and packages/sources/README.md from https://github.com/unitdhda/jobseeker.
Ask for missing choices and credentials without exposing or committing secrets. Initialize only an empty database,
configure deployment-owned source extensions, preserve exactly one Telegram receiver, and get `jobseeker doctor` plus
/health and /ready passing before handing back.
```

Чтобы дорабатывать само приложение, клонируйте репозиторий:

```bash
bun install --frozen-lockfile
bun run typecheck
bun run test
bun run build
bun run test:postgres  # нужна отдельная настроенная тестовая база
```

Детерминированные тесты не загружают локальные env-файлы разработчика и не обращаются к живым моделям.

## Технический обзор

Jobseeker — строгий TypeScript ESM-монорепозиторий на Bun workspaces, работающий на Node или Bun. Доменные пакеты
разделены проверяемыми границами импортов; `packages/app` собирает их вместе и публикуется в npm.

| Workspace | Ответственность |
|---|---|
| `packages/engine` | Чистые контракты конвейера, идентичность, сопоставление, ритм, бюджеты, параллелизм, состояния и цикл |
| `packages/store` | Собственный пул PostgreSQL, транзакции, блокировки и именованные репозитории |
| `packages/sources` | Изолированный runtime источников, SSRF-безопасный HTTP, парсеры и универсальные драйверы |
| `packages/cv` | Безопасное извлечение CV, канонические документы, проверка фактов и PDF через Typst |
| `packages/app` | CLI, конфигурация, композиция, AI, workflow, воркеры, Telegram, HTTP, расширения и схема базы |

Разрешённый внутренний граф: `sources → engine`, `store → engine + cv` и `app → все домены`; у `engine` и `cv` нет
внутренних workspace-зависимостей. Доменные пакеты не читают `process.env`, провайдеры источников не импортируют
PostgreSQL, а runtime приложения обращается к именованным репозиториям вместо сырого SQL.

PostgreSQL — единственное runtime-хранилище. `packages/app/schema.sql` — полная схема новой установки, а не серия
миграций. Исходные загруженные файлы и байты готовых PDF не сохраняются. Состояние браузера или OAuth можно шифровать
AES-256-GCM в совместимом объектном хранилище.

## AI-провайдеры и стоимость

Все вызовы проходят через [Pi AI](https://github.com/earendil-works/pi-ai). Модели выбираются конфигурацией:

- `AI_MODEL` — карьерные/поисковые профили и материалы для отклика;
- `AI_SCORING_MODEL` — полная оценка вакансий;
- `AI_PRESCORING_MODEL` — опциональный дешёвый семантический фильтр;
- `AI_SCORING_FALLBACK_MODEL` — опциональная резервная модель скоринга;
- `AI_AUTH_FILE` — хранилище учётных данных по провайдерам.

Встроенные провайдеры могут использовать API-ключи или OAuth, а расширения — регистрировать дополнительные.
`usage_events` хранит ID моделей, классы токенов и оценку стоимости по каталогу. Для OAuth и подписок это
эксплуатационный учёт, а не обязательно сумма из счёта.

## Приватность

Jobseeker обрабатывает резюме и поисковые предпочтения. Оператор отвечает за защиту PostgreSQL, Telegram-токена,
учётных данных моделей, расширений и ключей шифрования runtime-состояния.

- Сервер Jobseeker не сохраняет исходный загруженный файл CV; Telegram может хранить его по собственным правилам.
- Результат извлечения остаётся временным preview до подтверждения; затем сохраняются авторитетный текст и каноническая структура.
- Тексты CV и вакансии отправляются настроенным моделям для профилей, оценки и адаптации.
- Пользователи разделяют формулировки поиска, но не имена, контакты или текст CV. Сопоставление, оценка, доставка и материалы остаются персональными.
- Адаптированное резюме проходит детерминированную проверку фактов по авторитетному CV.
- Текст письма и Telegram file ID для PDF могут кэшироваться; байты готового PDF в PostgreSQL не хранятся.
- `/export_me` экспортирует сохранённые персональные данные; `/delete_me confirm` удаляет CV, профили, совпадения, материалы, usage и настройки доставки пользователя.

Перед обновлениями создавайте и проверяйте восстановлением резервные копии PostgreSQL, конфигурации окружения,
расширений развёртывания и ключей шифрования.

## Статус проекта

Jobseeker — используемый в продакшене персональный сервис для небольшого числа пользователей в одном развёртывании.
Он предполагает оператора, знакомого с Docker, PostgreSQL, Telegram-ботами, расширениями источников и учётными данными
моделей.

Проект активно разрабатывается. Перед тем как давать доступ другим пользователям, изучите схему, правила приватности,
расширения и руководство по развёртыванию.
